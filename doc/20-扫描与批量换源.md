# 扫描与批量换源：`scan` / `plan` / `setup`

`chsrc` 原本是「一次处理一个菜品」的模型。为了减少初始化一台新机器时的重复操作，
本补丁增加了三个命令，形成「发现 → 计划 → 执行」的闭环：

```bash
chsrc scan     # 只读：检测本机有哪些可换源项目，以及它们当前用的源
chsrc plan     # 只读：生成一份换源方案
chsrc setup    # 执行：确认后逐项换源
```

<br>

## 为什么不直接做 `set all`

直接把所有菜品都换一遍有三个现实问题：

1. **已安装 ≠ 应该换源**。机器上装了 Python，不代表用户希望改动 pip、poetry、pdm。
2. **某些源不能一概而论**。公司私有 npm registry、内部 PyPI、代理环境一旦被覆盖，
   排查成本很高。
3. **权限与半自动项混杂**。系统源需要 root，conda / Docker 等 recipe 是半自动或手工的，
   不适合静默批量执行。

因此 `setup` 的核心不是「全部换掉」，而是**有边界的批量执行**。

<br>

## `scan`：只读检测

```bash
chsrc scan
chsrc scan --deep      # 逐个调用包管理器核实当前源（较慢但更准）
chsrc scan --lang      # 只看编程语言与包管理器
chsrc scan --ware      # 只看软件
chsrc scan -en         # 英文输出
```

输出会列出：

- 检测到的菜品（dish）
- 自动 / 系统级 / 手工 的分类
- 检测依据（命令名、配置文件或 `os-release`）
- 当前源状态：`上游默认` / `已知镜像` / `未配置` / `自定义(保护)`

`scan` 不会修改任何文件，也不会执行 `chsrc set`。

> 为了速度，默认模式读取已知配置文件与环境变量；`--deep` 才会逐个调用
> `npm config get registry`、`go env GOPROXY` 等命令。

<br>

## `plan`：生成方案

```bash
chsrc plan
chsrc plan --mirror=ustc
chsrc plan --first
chsrc plan --lang --force
```

每一项会显示 `[执行]` 或 `[跳过]`，以及跳过原因。

<br>

## `setup`：执行

```bash
chsrc setup                 # 交互确认
chsrc setup -y              # 跳过确认
chsrc setup -dry            # 只打印，不执行
chsrc setup --mirror=ustc   # 指定镜像站
chsrc setup --first         # 使用维护团队测速第一的源
```

如果不指定镜像站，每一项会走 recipe 自身的「自动测速选最快源」逻辑。

<br>

## 默认安全边界

`setup` 默认**只执行**：

- 用户级或项目级
- 全自动
- 当前源不是自定义源

默认**只列出不执行**：

| 情况 | 行为 |
| --- | --- |
| 系统级源（APT、pacman 等） | 需要 `--include-system` 且以 root/管理员运行 |
| 半自动 / 手工 recipe（conda、Docker 等） | 只提示，建议单独 `chsrc set` |
| 检测到自定义源 | 默认保护，需要 `--force` 才覆盖 |
| 可能写入 HOME 之外的 recipe | 不纳入批量，建议单独执行 |

<br>

## 选项一览

| 选项 | 说明 |
| --- | --- |
| `--all` / `--include-system` | 纳入系统级项目（仍需 root/管理员） |
| `--lang` | 仅编程语言与包管理器 |
| `--ware` | 仅软件 |
| `--first` | 使用 `first` 而非自动测速 |
| `--mirror=<code\|url>` | 指定镜像站或自定义 URL |
| `--force` | 允许覆盖识别为自定义源的配置 |
| `--yes` / `-y` | 跳过交互确认 |
| `--deep` | 逐个调用包管理器核实当前源 |
| `-dry` | 只打印，不执行 |
| `-en` | 英文输出 |
| `-no-color` | 无颜色 |

<br>

## 示例

```bash
# 1. 看看机器上有什么
chsrc scan

# 2. 生成方案并检查
chsrc plan --lang

# 3. 只换编程语言相关的源
chsrc setup --lang

# 4. 指定镜像站，跳过确认
chsrc setup --lang --mirror=ustc -y

# 5. 预览系统级方案（不会执行）
chsrc plan --all -dry
```

<br>

## 实现说明

每一项都通过重新执行 `chsrc set <dish> ...` 完成，这样做的好处是：

- 复用既有 recipe，不在批量层重复实现换源动作
- 每项在独立进程中执行，单项失败不会中断整批
- 可以准确统计成功 / 失败 / 跳过

新增的 `scan` / `plan` / `setup` 命令实现在 `src/framework/bulk.c`，
检测表位于同文件顶部的 `BulkProbes`。
