# 开发 chsrc

## 依赖与开发环境

请安装好：

  1. `GCC` 或 `Clang`
  2. [just] 或 `make`
  3. `curl`
  4. [rawstr4c] (可选)

**我推荐你使用 VS Code 开发，你可以在一分钟内成功编译、运行和 Debug `chsrc`**

  1. `Ctrl-Shift-B` 直接构建
  2. `F5` 直接开始 Debug

<br>



## 获取代码

**请务必使用 dev 分支开发**

```bash
git clone https://gitee.com/RubyMetric/chsrc.git -b dev
```

关于分支的说明，可参考 [./03-CONTRIBUTING.md](./03-CONTRIBUTING.md)

<br>



## 编译运行

共有四种构建模式：

1. **`DEV mode`**
2. **`DEBUG mode`**
3. **`RELEASE mode`**
4. **`CI-RELEASE mode`**

开发时只需要前两种模式；第四种模式只在 GitHub Actions 使用。

**如果你使用 `just`，可以在 VS Code 中获得更好的体验，按 `Ctrl-Shift-B` 直接使用 DEV mode 构建**

**注意: `DEBUG` 模式下, 执行任意一个 `recipe` 的任意操作，会额外检查所有 `_prepare()` 是否能正常工作，如: `./chsrc-debug ls <recipe>`**

```bash
just (b)      # 在Windows上默认使用 gcc 编译，在macOS上默认使用 clang 编译，在其他系统上默认使用 cc 编译
just CC=clang # 使用 clang 编译
just CC=gcc   # 使用 gcc   编译

# 编译出 debug 版本: chsrc-debug
just bd
# 编译出 release 版本: chsrc-release
just br
```

<br>

`make` 用户:

```bash
make (b)      # 在Windows上默认使用 cc 编译，在macOS上默认使用 clang 编译，在其他系统上默认使用 cc 编译
make CC=clang # 使用 clang 编译
make CC=gcc   # 使用 gcc   编译

# 编译出 debug 版本: chsrc-debug
make bd
# 编译出 release 版本: chsrc-release
make br
```

<br>



## Debug

**如果你使用 `just`，可以在 VS Code 中获得更好的体验，按 F5 即可立即开始 Debug**

```bash
# 重新编译出 ./chsrc-debug，并启动 GDB 调试 (在macOS上启动 LLDB 调试)
$ just debug

# 重新编译出 ./chsrc-debug，并启动 LLDB 调试
$ just DEBUGGER=lldb debug
```

<br>

`make` 用户:

```bash
# 重新编译出 ./chsrc-debug，并启动 GDB 调试 (在macOS上启动 LLDB 调试)
$ make debug

# 重新编译出 ./chsrc-debug，并启动 LLDB 调试
$ make debug DEBUGGER=lldb
```

<br>



## 测试

`just` 用户只需要替换下述 `make` 为 `just`

```bash
make test-xy  # 测试 xy.h
make test-fw  # 测试 framework
make test-file-update # 测试通用 POSIX 文件更新层（不依赖 env 模块）
make test     # 测试基础库、framework 及当前平台支持的文件/环境变量回归
make test-cli # 测试命令
make test-env # POSIX 环境变量集成回归（Python 3；Bash/Fish，安装 Zsh 后额外验证 Zsh）
make clean
```

<br>



环境变量测试在独立临时 HOME 中执行，不能以运行中修改 HOME 替代隔离：
`xy_os_home` 会缓存首次查询结果。`make test` 在 POSIX 上包含 `test-env`；
`just` 用户可单独运行 `just test-env`。测试使用实际 shell 检查配置生效，
并验证复杂配置保护、文件权限、写入失败回滚及调用者 HOME 保持原样。

`make test-file-update` / `just test-file-update` 独立编译文件更新层，验证二进制内容、
字节相同时零写入、Dry Run、旧快照冲突、符号链接、重复目标和失败回滚。
POSIX `make test` 与 `just test` 包含它；Windows 下该程序编译后明确跳过 POSIX 更新测试。

POSIX 配置更新先暂存文件并检查写入/关闭结果，再逐文件替换，后续失败会回滚。
不保证进程崩溃或断电时的跨文件事务；无法安全解析的 here-document、
多行命令替换以及目标变量位于条件块/函数体等情况会在修改前拒绝。
